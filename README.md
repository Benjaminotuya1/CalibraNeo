# CalibraNeo

CalibraNeo is a provenance-aware research workflow for analysing putative
mutant peptide-HLA shortlists. It combines biophysical features, a calibrated
classifier, HLA-panel/provenance sensitivity analysis, and a transparent
LOH-aware cassette-selection heuristic.

It is **not** a diagnostic, therapeutic, or clinical vaccine-design system.
Its outputs are analytical shortlists that require independent MS and/or
T-cell validation.

## Quick start

Install runtime dependencies:

```powershell
python -m pip install -r requirements.txt
```

Rebuild the leakage-safe model and benchmark:

```powershell
python -m calibraneo.cli train
```

Run the LOH-aware simulation:

```powershell
python -m calibraneo.cli optimize
```

Regenerate the notebook and figures:

```powershell
python -m calibraneo.cli figures
```

Fetch a bounded official IEDB evidence sample:

```powershell
python -m calibraneo.cli external-data
```

Build the candidate-level computational validation report and experiment queue:

```powershell
python -m calibraneo.cli validation
```

Run grouped leakage, bootstrap confidence-interval, external-shift, and HLA
subgroup audits:

```powershell
python -m calibraneo.cli audit
```

Train the endpoint-specific models that have supported local labels:

```powershell
python -m calibraneo.cli endpoint-models
```

Freeze predictions and hashes before laboratory testing:

```powershell
python -m calibraneo.cli freeze
```

Build the comparator availability table:

```powershell
python -m calibraneo.cli comparators
```

Train the available gene-level RNA stability context model:

```powershell
python -m calibraneo.cli rna-model
```

This model uses the downloaded RNADecayCafe table. It estimates gene-level
half-life context only; it does not prove that a custom mRNA vaccine ORF will
be stable or translated.

Combine the available T-cell sources and run a leave-one-study-out audit:

```powershell
python -m calibraneo.cli combined-immunogenicity
```

This currently harmonizes the bounded IEDB T-cell sample with the Ott cohort.
The report is intentionally allowed to fail: in the current run the unseen
Ott study is approximately random (AUC 0.50). That result prevents us from
claiming that the immunogenicity model generalizes across studies.

Build the computational stopping-gate report:

```powershell
python -m calibraneo.cli gate
```

The gate separates three categories: completed computation, unavailable or
access-controlled data, and claims that require wet-lab validation. The
current release is computationally complete for the locally available data,
but it is not a clinical or biological proof system. It is the stopping point
until additional licensed datasets or laboratory outcomes arrive.

Patient-specific inputs now include HLA, expression, allele-specific
expression, HLA-LOH, HLA copy number, and supplied mutant-protein context.
The last item can generate peptide windows around a mutation. A complete
VCF-to-peptide workflow still requires transcript selection, consequence
calling, and a reference protein database; the parser does not invent those
missing biological facts.

The audit writes `results/validation_audit_report.json`. In the current run,
the grouped internal holdout is strong, Zenodo transfer is moderate, and the
Ott clinical-vaccine cohort is below random ranking. The Zaghla-derived table
is explicitly excluded from independent-validation claims because its filled
binding-rank field perfectly separates the imported labels. These failures are
retained in the report rather than hidden.

### Publication-hardening audit

Run the reproducibility hardening audit with:

```powershell
python scripts/30_harden_validation_and_loh.py
```

This writes `results/split_manifest.csv` and
`results/split_source_label_counts.csv` with the source, model partition,
exact peptide-HLA group, and label for every master-dataset row. It also writes
the exact-group overlap audit, leave-one-source-out results, group-aware
bootstrap intervals, calibration slope/intercept tables, prevalence-referenced
reliability data, and a decision-curve data table. The corrected Nature audit
reports nine exact peptide-HLA groups overlapping the training pool and writes
an overlap-excluded prediction file rather than silently calling the raw
cohort independent.

The same script writes `results/shared_score_loh_sensitivity.csv`, which uses
one frozen presentation score for all selector policies and covers dominant,
random single-allele, and two-allele loss scenarios at secondary loss
probabilities of 0.05, 0.10, 0.20, and 0.30, with empirical 95% intervals over
200 simulated patients. `results/exact_dp_reference.json` records a bounded
exact hierarchical Poisson-binomial reference selection for small pools; it is
not a scalable MILP implementation. No real patient HLA-LOH calls were used.

`Manuscript_hardened_revision.docx` is generated by
`scripts/31_harden_manuscript.py` without overwriting the author-supplied
`Manuscript.docx`.

### Thesis platform extensions

The platform extension layer is implemented in `calibraneo/platform.py`.
It adds:

- dual-mode shared-antigen scoring and allele-frequency-weighted population
  coverage from user-supplied HLA frequencies;
- circRNA BSJ, local-structure, IRES compatibility, and rolling-translation
  proxy features;
- literature-curated cytokine-triplet ranking with explicit synergy,
  antagonism, and risk proxies;
- versioned hand-off contracts for future IRES and LNP-QSAR models.

Public resources are registered in `data_registry_platform.json`. Raw data are
not copied into the repository because public availability does not by itself
establish redistribution rights. The circRNA and cytokine scores are
hypothesis-ranking proxies, not validated biological predictions. The LNP
interface is a contract until a licensed formulation/outcome table is obtained.

The circRNA module now treats BSJ frame continuity and IRES length compatibility
as hard constraints. It uses ViennaRNA `RNAfold` when installed and reports an
explicit fallback status when it is unavailable; the reverse-complement
self-complementarity value is retained only as a secondary descriptor. The
rolling-translation proxy is defined as a weighted combination of BSJ frame
continuity, complete codon traversal, in-frame stop avoidance, and GC
compatibility. It is not a translation model. These sequence-level constraints
have not been validated against measured circularisation efficiency or
translation yield.

The planned retrospective benchmark is tracked in
`circRNA_benchmark_manifest.json`. It is intentionally not populated with
invented sequences or assay labels: each construct must be traceable to a
primary record or permitted accession before it is scored. The contribution
being evaluated is cassette-level design on top of a circular backbone and
IRES, not the circular backbone itself. This is orthogonal to the published
scarless circularisation work, which established improved circular RNA
production and expression.

Once a permitted construct table is available, run the retrospective benchmark
with:

```powershell
python scripts/32_benchmark_circRNA.py `
  --input path\to\permitted_circRNA_constructs.csv `
  --output results\circRNA_constraint_benchmark.csv
```

The runner does not infer labels from publication status. It reports
construct-level scores and calculates Spearman correlations only for measured
circularisation or translation outcomes with at least three non-missing values.

The endpoint model manifest distinguishes trained models from unavailable
datasets. The current local build can train an Ott T-cell-response model and a
Zaghla-derived immunopeptidomics model. TESLA, NEPdb, NeoDB, HLA Ligand Atlas,
SysteMHC Atlas, TTDB, and RPFdb are tracked as sources but are not claimed as
trained inputs until normalized files are available and license conditions are
checked. A public RNADecayCafe gene-level half-life table is now downloaded
under `data_external/rna/` and used for a separate gene-context model; it is
not a custom vaccine-ORF stability predictor.

Manuscript assets are generated by
`scripts/29_generate_manuscript_assets.py`. Figure 2 includes the internal
test-set prevalence baseline and reports 10 equal-width calibration bins.
Figure 3 separates direct frozen Nature evaluation from the within-cohort OOF
benchmark. Figure 4 now reports stochastic P(S >= 2) and complete-failure outcomes from
explicit Bernoulli presentation and HLA-loss draws. These are hypothetical
Monte Carlo results using 2,000 patients and seed 42, not patient-level
estimates. Selection is performed before the simulated LOH state is drawn;
binary outcome intervals use Wilson 95% intervals.

## What the current model means

The Stage 1 model combines a gradient-boosted classifier and an MLP over
biophysical/HLA features. Calibration is fitted on a separate split and
evaluated on an untouched test split.

The Stage 2 benchmark reports both:

- a biophysics-only model; and
- a tool-fusion model that uses competing predictor outputs as inputs.

The fusion model is therefore not an independent replacement for those tools.
The current results show improved probability calibration but not superior
ranking AUC on the clinical benchmark.

External IEDB T-cell and MHC-ligand assays are written to
`data_external/iedb/` as a separate evidence layer. They are not merged into
the local presentation-label master table because they represent different
biological endpoints. Full snapshots and restricted datasets require explicit
access and licence review.

### Endpoint validation and combination boundary

Run:

```powershell
python scripts/33_build_endpoint_status.py
```

This writes `results/endpoint_validation_status.json`. The registry records
which endpoints are currently trainable and which have internal or external
validation. It is intentionally conservative: presentation and
immunogenicity are separate endpoints; the RNA model is gene-level context;
and circRNA translation, LNP delivery, tumour killing, and cytokine safety are
not currently validated prediction models.

Endpoint models can be trained individually when a dataset has compatible
labels, features, and independent groups. Their outputs can then be combined
with `combine_endpoint_predictions`, but only as an uncertainty-aware
decision-layer score. A combined score is not a new experimentally validated
outcome and cannot infer tumour killing or safety from presentation evidence.
Missing endpoint measurements remain unknown and reduce completeness.

## How computational validation works

The validation layer keeps each biological question separate:

- the versioned presentation model produces `CalibraNeo_Prob`;
- exact IEDB peptide-HLA matches are attached as external evidence;
- missing immunogenicity, translation, and RNA-stability measurements remain
  unknown;
- a transparent composite ranks candidates using only observed components;
- uncertainty and evidence completeness are reported beside the score;
- the experiment queue recommends the next missing assay for each candidate.

The queue is a prioritization tool, not proof that a vaccine will work. A
credible computational validation package should report an untouched test set,
calibration, external dataset provenance, grouped leakage controls, ablations,
confidence intervals, and failure cases. It cannot establish patient response,
safety, delivery, or therapeutic benefit without laboratory and clinical data.

Public resources are tracked in `data_registry.json`, including IEDB, TESLA,
SysteMHC Atlas, HLA Ligand Atlas, NEPdb, NeoDB, RPFdb, TTDB, and
RNADecayCafe. Historical biomedical data are heterogeneous and do not span a
single comparable 100-year training series; CalibraNeo therefore records
source, endpoint, access, and license status instead of blindly concatenating
them.

## Explicit stopping rule

Computational expansion stops when the following are true:

1. every accessible dataset is provenance-checked and kept endpoint-specific;
2. grouped internal and independent-study validation has been run;
3. leakage and label-derived proxies have been audited;
4. available comparators are run or marked unavailable;
5. patient-input quality checks and prediction freezing are complete; and
6. every remaining gap is either data access, a missing reference dependency,
   or a wet-lab/clinical question.

This rule is part of the scientific design. A lower score on an unseen cohort
is a result to report, not a reason to keep adding complexity until a desired
number appears.
